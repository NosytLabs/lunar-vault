### Positive minimumRoundDuration — intentionally fail-closed; real-profile support unresolved

Lunar rejects a positive authenticated duration with an unsupported-setting error (`packages/components-shared/src/components/Authenticate.svelte:45`–`:54`); Salmon does likewise in `apps/salmon-run/src/engine.ts:164`–`:172`. The 700 ms / 350 ms local presentation floor is not claimed to implement that server field. Fresh fail-closed cases pass for positive values; ordinary zero/missing profiles work.

The [official wallet documentation](https://studio.engine.io/docs/rgs/wallet) shows minimumRoundDuration: 0 without specifying units. A complete official SDK scan at commit `1843d60cedb94b390e641b563f32ad64353bec5e` examined 889 TS/Svelte/JS/MJS/MD files with zero fetch errors and found exactly three literal references: a commented 0 example in [Authenticate.svelte#L59](https://github.com/engineio/web-sdk/blob/1843d60cedb94b390e641b563f32ad64353bec5e/packages/components-shared/src/components/Authenticate.svelte#L59), a number schema in [schema.ts#L226](https://github.com/engineio/web-sdk/blob/1843d60cedb94b390e641b563f32ad64353bec5e/packages/rgs-fetcher/src/schema.ts#L226), and default 0 in [stateConfig.svelte.ts#L14](https://github.com/engineio/web-sdk/blob/1843d60cedb94b390e641b563f32ad64353bec5e/packages/state-shared/src/stateConfig.svelte.ts#L14). No positive-value handling or unit definition was found. The reproducible source-scan record is [engine-duration-source-review-20261028.json](engine-duration-source-review-20261028.json).

**Required external action:** obtain the intended units/semantics and a real Engine profile; implement and verify positive duration before releasing into profiles that require it. Keep such profiles blocked until then. This is not a declaration that all jurisdictions are supported.
